Design Principles

1 Max 4 menu items

Every menu has at most 4 options plus "0. Back/Exit". Fewer choices = faster decisions = more screens within the 180s timeout.

2 One question per screen

No compound inputs. Each screen asks one thing. Weight on one screen, grade on the next, price after that. Zero chance of format errors on feature phones.

3 Contact on every close

Every acceptance or "I can supply" screen shows the other party's phone + location. SMS mirrors this. Digital → physical immediately.

4 PIN on every session v2.2

Every session starts with a 4-digit PIN — just like MoMo. Builds trust, prevents SIM-swap fraud, and ensures only the account holder can transact. PIN entry takes ~8 seconds (fast muscle memory).

Agent-registered vs self-registered: When an agent registers a collector, they set a temporary PIN and give it to the collector verbally. UX/UI Improvements (v2.2)

Improvements already applied in this spec:


1. Ratings visible in listings. When a collector browses buyers or reviews an offer, the aggregator's star rating is shown (e.g., "★★★★☆ (4.2)"). This builds trust and rewards good actors — a key feedback loop for the whole system.


2. Pagination on all list screens. Results screens show 3 items + "4. More results" instead of assuming everything fits on one screen. When there are 20 PET sellers in Accra, users can page through 3 at a time without overwhelming the screen. Back always available via 0.


3. Business names instead of IDs. In collector-facing screens, aggregators are shown by business name ("Kofi Aggregates") rather than ID codes ("AGG-0002"). IDs are still used in aggregator-facing screens for collectors (privacy: "COL-0001") per existing privacy rules, but the partner context is more human.


4. SMS notification templates with transaction references. Every SMS includes a TXN reference number (like MoMo receipts). SMS is the durable record for illiterate or semi-literate users who ask someone to read it later. Section added above.


5. Error states designed explicitly. Wrong PIN, account lockout, and first-login PIN change flows are all shown with real screens — not just described in text. These edge cases are critical for first-time users who will inevitably mistype their PIN.


6. Contextual breadcrumbs on every screen. Each data entry screen shows what the user has already entered (e.g., "HDPE · 500 kg · Clean" on the price screen). This reduces the "where am I?" confusion common on USSD and lets users verify their choices before committing.


7. Trivial PIN rejection. Registration flows explicitly warn against 0000 and 1234 and reject them server-side. Simple security measure that prevents the most common weak PINs without adding friction.

Improvements to consider for implementation (not in spec yet):


A. "00" as universal shortcut to main menu. Instead of pressing 0 repeatedly to navigate back, "00" jumps straight to the main menu from any depth. Saves time on deep flows. Common pattern in West African USSD services.


B. PIN change option. Under My Activity, add "Change PIN" (4 screens: current PIN → new PIN → confirm → done). Low priority but important for users who suspect someone saw their PIN, or who forgot and had it reset.


C. "No results" empty states. When there are no listings, no offers, or no pending transactions — show a helpful message instead of nothing. E.g., "No PET buyers in Accra right now. Try posting a Sell listing instead! Dial → Marketplace → Sell."


D. Twi language option. After PIN, show "1. English / 2. Twi" before the main menu. Adds 1 screen but could dramatically improve accessibility in rural areas. Could defer to v3 and test with English-only first.


E. Listing expiry reminder SMS. 24 hours before a listing expires, send an SMS: "Your 80kg PET listing expires tomorrow. Dial *920*123# to relist if it hasn't sold." Keeps the marketplace active without requiring users to check.


F. "Repeat last action" shortcut. If a collector logs the same type of drop-off daily, the main menu could show "Quick: Log 50kg PET to Kofi Agg?" as a fast-path option 1. Saves 4 screens for repeat users. Complex to build — defer to v3.

UX Improvements — Detailed Flows (A through E)

A. "00" Universal Shortcut to Main Menu


Typing 00 at any screen immediately returns to the main menu without walking back through every level. This is a common pattern in West African USSD services (MTN, Vodafone, AirtelTigo all use it). Implementation is simple: the USSD handler checks if the latest input segment is "00" and, if so, resets the navigation state to depth 0.

Deep in a flow

E. Listing Expiry Reminder SMS


24 hours before a listing expires, send an SMS nudge. This keeps the marketplace active without requiring users to check. Server-side cron job runs daily at 8am, queries listings expiring in the next 24 hours, sends SMS via Arkesel API.
