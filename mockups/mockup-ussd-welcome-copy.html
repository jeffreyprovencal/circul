USSD Unregistered Welcome — Copy Variants

First-time dialers hitting *920*54# from an unregistered phone see handleUnregisteredUssd's depth-0 screen. Today's version is bare (2 menu items, no context). This mockup enumerates copy variants so we pick the right one before coding. Pick A/B/C/D (or mix), I'll revise claude-code-prompt-ussd-welcome.md to match.

Today — what dialers actually see right now on prod
Shipped in the initial USSD build, pre-PR-58. Two menu items, no value prop, no brand anchor. First impression for every new Ghanaian dialer including the WORK-network collectors Pat might send our way.
*920*54#MTN GH
CON Welcome to Circul 1. Register 2. Exit
Current · 35 chars
Inconsistent with the rest of the USSD system, which uses 0 for back/cancel/exit. The 2 here is a leftover from early development.
Option A — Terse value prop
Minimal addition. One line, six words. Fixes the menu-number inconsistency. Closest to the current feel; lowest risk of AT truncation.
*920*54#MTN GH
CON Welcome to Circul Sell recyclables for income. 1. Register 0. Exit
Option A · ~65 chars

Pros

  • Shortest addition — minimal gateway truncation risk
  • "Sell recyclables for income" is action-oriented, user-readable in 2 seconds
  • Fixes the 2 → 0 design-rule inconsistency
  • No new code paths — one line copy change + one branch fix

Cons

  • Doesn't name the brand context — no "Ghana", no "waste economy", no aggregator mention
  • No "learn more" path for curious first-timers — they either register or exit
  • "Income" may over-promise for collectors who don't know the economics yet
Option B — Brand + user-target framing
Adds a second line naming the target user and what they do with Circul. Slightly longer but grounds the pitch.
*920*54#MTN GH
CON Welcome to Circul Ghana's marketplace for waste collectors. 1. Register 0. Exit
Option B · ~85 chars

Pros

  • Anchors the geography ("Ghana") — reassures that this isn't a scam foreign platform
  • Names the user ("waste collectors") — if a non-collector dials, they know to exit early
  • Still well under the 182-char GSM limit
  • "Marketplace" signals two-sided platform (buyers + sellers)

Cons

  • Doesn't tell them what they gain — no "income" or "fair prices" hook
  • "Waste collectors" language might feel undignified to some users — consider alternatives like "recyclables collectors" or "recyclers"
  • Aggregators who dial will see "waste collectors" and bounce — even though they ARE supposed to register (via the invite-code path once that UX lands on USSD)
Option C — "What is Circul?" info branch
Adds a third menu option (2. What is Circul?) that leads to a one-screen explainer with contact info. Costs one small new branch in handleUnregisteredUssd. Gives curious first-timers a way to learn before committing to registration.
*920*54#MTN GH
CON Welcome to Circul Sell recyclables for income. 1. Register 2. What is Circul? 0. Exit
Option C · screen 1 · ~95 chars
*920*54*2#MTN GH
END Circul is Ghana's recycling marketplace. Collectors sell waste to aggregators who pay fair prices by weight. Support: 0300000003 Learn more: circul.app
Option C · screen 2 · info END
END screen — dial *920*54# again to register. Contact + web for follow-up. Total ~150 chars.

Pros

  • Curious first-timers can learn without committing — reduces "what IS this?" registration abandonment
  • Shows support phone + URL — professional, reachable, not a fly-by-night feel
  • Second screen can be tweaked independently as the pitch evolves (e.g. when we add brand-tier messaging post-WORK-call)
  • 3 menu items + 0. Exit = exactly 4 total, stays inside the max-4-items design rule

Cons

  • Adds a new code branch — bigger PR scope
  • Support phone in the copy means we need a real support phone — do we have one? (0300000003 is Kofi Mensah the demo agent — not a real support line)
  • Info screen hard-codes the marketplace framing — needs updating when the brand-tier pitch lands
  • circul.app domain status: per memory, domain is via cyon but pending Polsia custom-domain setup — is it resolving yet?
Option D — Role split (Collector vs Aggregator)
Acknowledges both user types that might dial in. Adds a role-choice screen before registration so aggregators land in the invite-code flow (once we ship that path). Most ambitious; also solves a design gap that comes up as soon as we add USSD aggregator registration.
*920*54#MTN GH
CON Welcome to Circul Ghana's recycling marketplace. Register as: 1. Collector 2. Aggregator 0. Exit
Option D · ~95 chars
*920*54*2#MTN GH
CON Aggregator registration needs an invite code from a processor or another aggregator. Enter invite code: 0. Cancel
Option D · aggregator path
Feeds into the invite-based aggregator registration from `project_circul_role_fraud_prevention.md` — currently NOT implemented on USSD. This option would force us to ship that path alongside the welcome copy change.

Pros

  • Solves the aggregator-registration USSD gap at the same time — one bigger win instead of two small ones
  • Invite-code flow has been designed in memory for a while; this gives it the entry point
  • Clearer routing — Pat's aggregator contacts can self-register via USSD without needing an admin to set them up

Cons

  • Meaningfully bigger scope — adds invite-code validation flow, database table (invites from memory §`project_circul_role_fraud_prevention.md`), SMS triggers
  • Not doable today — would spill into post-holiday
  • If an aggregator dials without an invite code, they hit a dead end — still a UX friction point
CTO recommendation

Option A for today, Option C as the natural follow-up

Ship A now: smallest change, clearest win, fixes the design-rule inconsistency, lands in today's second Polsia credit. Closes a visible wart without expanding scope.

Queue C as a small post-holiday PR: the info-screen path is worth doing, but it hinges on two things that need resolution first — (1) a real support phone number or channel we're comfortable putting in USSD copy, (2) circul.app resolving cleanly. Neither blocks A; both block C. So ship A now, draft C when those two are confirmed.

Defer D indefinitely until Miniplast pilot signal on USSD aggregator registration demand. Memory's invite-code flow is the right design but the cost is non-trivial (schema + SMS + validation) and we have no live demand signal yet.
