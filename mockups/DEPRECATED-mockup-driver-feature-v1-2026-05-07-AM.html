Driver actor MVP — feature mockup

Visual review of every new screen and message in the driver feature, before any code ships. Surfaced by WORK 2026-05-06 — drivers are the field actors who collect aggregator delivery receipts. Phone-only auth (no PIN), USSD-accessible, sub-account of an aggregator. Target ship 2026-05-13.

Sections

  1. Aggregator registers a driver — USSD flow (5 screens)
  2. Welcome SMS to driver
  3. Driver dials *920*54# — main menu + 3 sub-flows
  4. Dispatch SMS — driver gets notified of assignment
  5. Aggregator dispatch flow — new "Assign driver" step
  6. Aggregator web dashboard — "My Drivers" section

Design constraints honored

Every USSD screen below respects: (a) Yam-phone visible-line cap of ~4-5 lines, (b) 4 menu items + 0-for-back maximum per feedback_ussd_design_rules.md, (c) no non-GSM-7 characters (no →, no cedi ₵) per feedback_ussd_at_session_timeout.md + AT docs warning, (d) total response body under 182 chars even with longest interpolated values. SMS templates are checked under 160 chars (single segment).
A. Aggregator registers a driver — USSD flow
The aggregator dials *920*54#, enters PIN, navigates to 1. Register. The submenu currently has Collector and Agent; we add Driver as option 3. Five-step flow mirrors the existing register-agent shape (first name → last name → phone → city → confirm), differs only in the success screen which shows the driver's DRV-NNNN code instead of a PIN reminder (drivers have no PIN — phone-only auth).

E. Aggregator dispatch flow — new "Assign driver" step
Today the aggregator's USSD sale flow ends with a confirm prompt. We add a driver-picker step between buyer selection and confirm. The step is optional: if the aggregator has no drivers registered, the picker is skipped entirely and the flow runs unchanged. If they have drivers, they pick one (or "skip" to record a dispatch with no driver assigned).

F. Aggregator dashboard — "My Drivers" section
New section on the aggregator dashboard. Read-only list of drivers belonging to this aggregator with stats per driver. Drivers are added via USSD only (no web add-driver form in MVP scope). Each driver row links to their activity log.

Explicitly out of MVP scope (deferred to post-rebuild)
