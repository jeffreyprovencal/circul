1. Current state — what's broken (2026-05-13)
Broken

Three independent issues stacked

  1. Wrong default period. Reports tab defaults to period: 'mtd'. Today is 2026-05-13 → MTD window = May 1 → Jun 1. Kwame's tagged transaction is pre-May seed data, so the window correctly contains 0 kg. Home tab shows 65 kg YTD because Home is YTD. → default mismatched to user mental model.
  2. PDF Unicode mangling. pdfkit's default Helvetica is WinAnsi-encoded. → renders as !'. · survives by coincidence. Header reads "Month to date · 2026-05-01 !' 2026-06-01". Methodology footnote reads "(collector!'aggregator)".
  3. Both files are unstyled. PDF is default-Helvetica with padEnd/padStart faking a table — reads like console output. Excel has a neon #00E676 title bar, no number formats, no banding, no borders, no totals row, footnote stranded in A5. Neither file has a real empty state — Excel has a blank row 4, PDF gives a one-line apology without telling Vivien her network has 65 kg YTD she could see by changing the period.

7. Excel — sheet 2: Methodology

Plain-language attribution rules. Lives inside the workbook so the file is self-contained — funder reviewers don't need to click out to a URL.

Excel · sheet 2 of 2: "Methodology"
circul-impact-report-work-ytd-2026-05-13.xlsx
2 sheets · Sheet 2 of 2
1 Attribution methodology · v1
2 1. First-tagged-touchpoint. A kilogram is attributed to an Impact Partner the first time it touches an actor that partner has tagged. The first tagged touchpoint earns the attribution; later touchpoints with the same or different partners do not earn it again.
3 2. No double-counting across partners. One transaction = one Impact Partner credit. If two partners both tag actors in the same supply chain, the partner whose actor is upstream (closer to the source) earns the credit.
4 3. v0 source-of-entry only. In this release, attribution counts only at the collector→aggregator handoff (where material enters the formal supply chain). Downstream-tagged actors (processors, recyclers, converters) do not add new kg in v0 — they will surface as program-context in a later release.
5 4. Tag approval gate. Every tagged actor was reviewed and approved by Circul against documented proof of an active support relationship from the Impact Partner. Tags can be removed at any time by the partner.
6 5. Window semantics. Year to date = 1 Jan of the current year through today. Month to date = 1st of the current month through today. All time = the full life of the platform.
7 Full methodology, including edge cases and roadmap: circul.app/methodology/impact-attribution-v1

8. Locked decisions (D1–D4)

All four decided 2026-05-13. Mockup §3–§7 reflect the locked state.

Locked

D1 — IDs only in PDF and Excel, no names anywhere in exports

Both formats render actor identity as the platform-standard ID code (COL-XXXX / AGG-XXXX / AGT-XXXX / DRV-XXXX). Names remain on the dashboard My Network tab only.

Reasoning: One rule platform-wide ("identifiers on the page, names on the screen") — matches the existing aggregator-report hard rule, no per-export anonymization decision. Cross-corroboration with aggregator reports happens via the shared ID schema, not via names. Names add re-identification surface area without paying for it. Option to relax later via opt-in Reports-tab toggle stays open.

Locked

D2 — Plus Jakarta Sans TTF committed to repo

Add public/fonts/PlusJakartaSans-Regular.ttf + PlusJakartaSans-Bold.ttf (~150 KB total, OFL 1.1) to jeffreyprovencal/circul. Deterministic builds; no Google Fonts dependency at Polsia deploy time.

Locked

D3 — Region column kept; PDF + Excel are row-for-row identical

Both tables: Tier · Actor ID · Region · Material · Kg · Txns (6 cols), sorted tier ASC, actor_id ASC, material ASC. Stable attributes (tier, actor, region) on the left; varying attributes (material, kg, txns) on the right. Each actor's rows cluster contiguously — reader scans left columns for groupings, right columns for activity. PDF and Excel are row-for-row identical; Excel adds filter/sort affordances Excel users expect.

Locked

D4 — Hero caption includes actor count + transaction count

PDF hero reads: "248 kg across 5 tagged actors and 12 transactions, first-tagged-touchpoint attribution". Network footprint is funder-helpful context (Coke wants to see how many actors a partner supports), and we're already disclosing it indirectly via row counts in Excel — making it explicit in the PDF caption is cleaner than fake-coyness.

10. Parked — Viv's downstream-tier tagging ask (v0.5, not 5b)

Surfaced 2026-05-13 by Vivien Luk. Captured here + in memory so the request doesn't get lost between Phase 5b and v0.5 scope-setting. Out of scope for Phase 5b — does not block the report-polish PR.

Parked

The ask

Vivien wants WORK's tagged network to cover every tier they engage with — not just collector / aggregator / agent / driver, but also processor, recycler, converter, brand. She wants to express "WORK supports this entity" across the whole supply chain, not just the entry tiers.

v0 truth

Where this lands against current methodology

  • Tag flow (server.js line 9622) currently allowlists collector / aggregator / agent / driver. Adding processor/recycler/converter is a 1-line allowlist extension + existing actor-lookup tables already exist.
  • Brand tier doesn't exist on Circul yet — separately parked in project_circul_brand_tier_recovery_credits.md. Cannot tag what isn't modelled.
  • Attribution v1 methodology already covers this case explicitly: "Downstream-tagged actors do not add new kg in v0." So a WORK-tagged processor would appear in My Network for transparency, but earn 0 kg attribution — kg attribution stays anchored to source-of-entry (collector→aggregator) per the no-double-counting rule.
v0.5 design Q

Open question for v0.5 scope-setting

If we surface a processor in WORK's network with 0 kg attribution, how do we communicate that without it looking like a broken UI? Options when we get there: (a) split My Network into "Attribution-earning" + "Supported (no attribution)" lists; (b) per-tier badge "v0 source-of-entry only" on downstream rows; (c) different methodology version that does pass-through attribution for downstream-tagged actors (would require re-thinking double-counting). Not a Phase 5b decision.
